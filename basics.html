-Algorithm
    --An algorithm is a set of well-defined instructions to solve a particular problem. It takes a set of input(s) and produces the desired output
    --Asymptotic notations
        ---Asymptotic notations are the mathematical notations used to describe the running time of an algorithm when the input tends towards a particular value or a limiting value
        ---The efficiency of an algorithm is measured with the help of asymptotic notations
        ---The efficiency of an algorithm depends on the amount of time, storage and other resources required to execute the algorithm
        ---There are mainly three asymptotic notations:
            ----Big-O notation
                -----Big-O notation represents the upper bound of the running time of an algorithm. Thus, it gives the worst-case complexity of an algorithm
                -----Graph: 
            ----Omega notation
                -----Omega notation represents the lower bound of the running time of an algorithm. Thus, it provides the best case complexity of an algorithm
                -----Graph: 
            ----Theta notation
                -----Theta notation represents the upper and the lower bound of the running time of an algorithm, it is used for analyzing the average-case complexity of an algorithm

    --Types of algorithms based on approaches or techniques that algorithms use to solve problems
        ---Brute Force
            ----Description
                -----Exhaustively tries all possible solutions and selects the one that satisfies the problem requirements
            ----Example
                -----Brute force string matching, exhaustive search
        ---Divide and Conquer
            ----Description
                -----Breaks down a problem into smaller, more manageable subproblems, solves them recursively, and combines their solutions to form the solution to the original problem
            ----Example
                -----Merge Sort, Quick Sort, Binary Search
        ---Greedy Algorithms
            ----Description
                -----Makes locally optimal choices at each stage with the hope of finding a global optimum
            ----Example
                -----Dijkstra's Algorithm for finding the shortest path, Huffman Coding for data compression
        ---Dynamic Programming
            ----Description
                -----Solves a problem by breaking it down into smaller overlapping subproblems and solving each subproblem only once, storing the solutions to subproblems and reusing them when needed
            ----Example
                -----Fibonacci Sequence, Longest Common Subsequence, Knapsack Problem
        ---Backtracking
            ----Description
                -----Tries to find a solution incrementally by exploring different paths and backtracks when it determines that the current path cannot lead to a valid solution
            ----Example
                -----N-Queens Problem, Sudoku Solver
        ---Randomized Algorithms
            ----Description
                -----Introduces an element of randomness to the algorithm, making its behavior non-deterministic
            ----Example
                -----Randomized Quick Sort, Monte Carlo algorithms
        ---Branch and Bound
            ----Description
                -----Systematically explores the solution space by dividing it into smaller subproblems and keeping track of the best solution found so far
            ----Example
                -----Traveling Salesman Problem, Job Scheduling
        ---Linear Programming
            ----Description
                -----Optimizes a linear objective function subject to linear equality and inequality constraints
            ----Example
                -----Simplex Algorithm
        ---Parallel Algorithms
            ----Description
                -----Executes multiple instructions simultaneously to speed up the computation
            ----Example
                -----Parallel Sorting Algorithms
        ---Heuristic Algorithms
            ----Description
                -----Uses rules of thumb or approximation techniques to find a near-optimal solution in a reasonable time
            ----Example
                -----Genetic Algorithms, Ant Colony Optimization
        ---Metaheuristic Algorithms
            ----Description
                -----Higher-level strategies or frameworks that guide the exploration of the solution space
            ----Example
                -----Simulated Annealing, Genetic Algorithms
        ---Online Algorithms
            ----Description
                -----Makes decisions in an online fashion, as data arrives, without having complete information
            ----Example
                -----Online Paging Algorithm

-Data structures
    --Data structure is a storage that is used to store and organize data. It is a way of arranging data on a computer so that it can be accessed and updated efficiently
    --Types of data structures 
        ---Linear data structures
            ----Array and strings
                -----Elements in memory are arranged in continuous memory
            ----Stack
                -----Elements are stored in the LIFO principle. That is, the last element stored in a stack will be removed first
            ----Queue
                -----The queue data structure works in the FIFO principle where first element stored in the queue will be removed first
            ----Linked list
                -----Data elements are connected through a series of nodes. And, each node contains the data items and address to the next node
        ---Non-linear data structures
            ----Graph
                -----Each node is called vertex and each vertex is connected to other vertices through edges
                -----Popular graph based data structures
                    ------Spanning tree and minimum spanning tree
                    ------Strongly connected components
                    ------Adjacency matrix
                    ------Adjacency list
            ----Tree
                -----Popular tree data structures
                    ------Binary tree
                    ------Binary search tree
                    ------AVL tree
                    ------B- tree
                    ------B+ tree
                    ------Red black tree

                    
-Edge case framework (ESTBMDISMP)
    --Edge cases are unusual or boundary conditions where an algorithm is more likely to fail. Instead of waiting for bugs to reveal them, systematically verify each category below
    --Empty input
        ---No data exists
        ---Examples
            ----Empty array
            ----Empty string
            ----Empty linked list
            ----Null pointer
    --Smallest input
        ---Test the minimum valid input
        ---Examples
            ----Single element array
            ----Single node linked list
            ----Single character string
    --Two elements
        ---Many algorithms fail with exactly two elements
        ---Examples
            ----Already sorted
            ----Reverse sorted
            ----Equal values
    --Boundary positions
        ---Operations performed at the beginning or end of a data structure
        ---Examples
            ----Insert at index 0
            ----Insert at last index
            ----Delete first element
            ----Delete last element
            ----Insert before head
            ----Insert after tail
            ----Delete head
            ----Delete tail
    --Maximum limits
        ---Test the largest valid input and extreme values
        ---Examples
            ----INT_MAX
            ----INT_MIN
            ----Full capacity
            ----Maximum number of nodes
        ---Check for
            ----Overflow
            ----Stack overflow
            ----Memory issues
    --Duplicate values
        ---Ensure repeated values do not break the algorithm
        ---Examples
            ----All values identical
            ----Multiple duplicate values
    --Invalid input
        ---Provide values outside the valid range
        ---Examples
            ----Negative index
            ----Index greater than size
            ----Null pointer
        ---Decide whether to reject, ignore or report the error
    --State transitions
        ---Verify every change in the state of the data structure
        ---Examples
            ----Empty -> One element
            ----One element -> Multiple elements
            ----Multiple elements -> One element
            ----One element -> Empty
    --Metadata updates
        ---Verify that all auxiliary information remains correct
        ---Examples
            ----Length or size
            ----Capacity
            ----Head pointer
            ----Tail pointer
            ----Height
            ----Parent pointer
            ----Balance factor
    --Pointer relationships
        ---After modifying pointers, ensure every remaining pointer is still valid
        ---Examples
            ----Deleting a node reconnects previous and next nodes correctly
            ----No dangling pointers
            ----No broken links
            ----No unintended cycles
    --Invariant checking
        ---An invariant is a condition that must always remain true before and after every operation
        ---Examples
            ----0 <= length <= capacity
            ----Array pointer is not null
            ----If size == 0 then head == nullptr and tail == nullptr
            ----If size > 0 then head != nullptr and tail != nullptr
            ----tail->next == nullptr
        ---After every operation, verify that every invariant still holds
